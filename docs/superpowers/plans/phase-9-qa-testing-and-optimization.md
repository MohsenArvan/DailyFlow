# برنامه اجرایی فاز ۹: تضمین کیفیت، تست‌های E2E و بهینه‌سازی (QA, Testing & Optimization)

> **سند مرجع فاز ۹ DailyFlow** — تست‌های سرتاسری مرورگر (Playwright E2E)، آزمون‌های فرانت‌اند، آدیت جامع دسترسی‌پذیری و رابط کاربری، و بهینه‌سازی حداکثری پرفورمنس (LCP و کوئری‌های پایگاه داده).

---

## ۱. هدف و معماری فاز ۹

**هدف فاز:** رساندن DailyFlow به بالاترین سطح پایداری و استانداردهای کیفی نرم‌افزار از طریق:
1. **تست‌های سرتاسری مرورگر (End-to-End Browser Testing با Playwright):** شبیه‌سازی دقیق رفتار کاربر واقعی در سناریوهای ثبت‌نام، ورود، مدیریت چرخه تسک‌ها، ایجاد پروژه و تعامل با شورتکات‌ها.
2. **آزمون‌های واحد و یکپارچگی استورهای فرانت‌اند (Vitest Testing):** پوشش تست برای استورهای Pinia (`auth`, `tasks`, `projects`, `dashboard`) و کامپوننت‌های حساس.
3. **آدیت دسترسی‌پذیری و ارگونومی رابط کاربری (Accessibility & UX Audit):** ارزیابی دقیق مطابق با استانداردهای WCAG 2.1 AA، هندلینگ Focus Trap در مودال‌ها، ناوبری کامل با کیبورد و کنتراست رنگ‌ها در هر دو حالت تاریک و روشن.
4. **بهینه‌سازی کارایی و سرعت (Performance Tuning):**
   - بهینه‌سازی زمان بارگذاری صفحه و شاخص LCP (Largest Contentful Paint).
   - تحلیل کوئری‌های دیتابیس، کشف و حذف تمام مشکلات کوئری‌های تکراری N+1.
   - ایجاد ایندکس‌های کامپوزیت کارآمد در PostgreSQL روی فیلدهای پرکاربرد جستجو و فیلتر.

| :--- | :--- |
| **`playwright-cli`** | راه‌اندازی، نگارش و اجرای تست‌های E2E مرورگر واقعی، اسکرین‌شات از وضعیت‌های خطادار، بررسی رندر کلاینت و فرم‌ها |
| **`web-design-guidelines`** | آدیت کامل فرم‌ها، دکمه‌ها، کنتراست‌ها، تگ‌های ARIA، پدینگ‌های لمسی (Tap Targets) و ناوبری بدون ماوس |
| **`debug-optimize-lcp`** | تحلیل زنجیره رندر اولیه، بهینه‌سازی لود فونت‌ها، استایل‌ها و استراتژی‌های Preload برای رساندن LCP به زیر ۱.۵ ثانیه |

## ۳. وظایف و اقدامات اجرایی گام‌به‌گام (Tasks & Steps)

### وظیفه ۱: سناریوهای تست سرتاسری مرورگر (Playwright E2E Suite)
- [ ] راه‌اندازی فایل پیکربندی Playwright یا تست‌های تعاملی با `playwright-cli`.
- [ ] سناریو ۱: **احراز هویت و پایداری نشست (Authentication Flow):**
  - ثبت‌نام کاربر جدید با فرم معتبر.
  - خروج از حساب و ورود مجدد با توکن پایدار.
  - بررسی هدایت خودکار کاربر محافظت‌شده از مسیرهای مهمان.
- [ ] سناریو ۲: **چرخه حیات تسک (Task Lifecycle Flow):**
  - ساخت تسک جدید با عنوان، تاریخ سررسید، اولویت و تگ‌ها.
  - ویرایش عنوان و اضافه کردن زیرتسک (Subtask).
  - تغییر وضعیت تسک به انجام‌شده و محو شدن/خط‌خوردن در نمای زنده.
  - انتقال تسک به سطل زباله / حذف دائمی.
- [ ] سناریو ۳: **مدیریت پروژه‌ها (Project Management Flow):**
  - ساخت پروژه جدید با رنگ و آیکون اختصاصی.
  - نشان‌دار کردن به عنوان برگزیده (Favorite) و مشاهده در سایدبار.
  - انتساب تسک به پروژه و بررسی شمارنده پیشرفت پروژه.
- [ ] سناریو ۴: **پالت فرمان سریع و کلیدهای میانبر (Command Palette `Cmd+K`):**
  - باز کردن پالت با کیبورد، جستجوی عنوان تسک، و رفتن مستقیم به آن.

### وظیفه ۲: آزمون‌های استورها و توابع فرانت‌اند (Frontend Unit Tests)
- [ ] نصب و پیکربندی Vitest در پروژه فرانت‌اند (`vitest.config.ts`).
- [ ] تست استور `useTaskStore`: بررسی اعمال صحیح فیلترهای زمانی (`today`, `upcoming`, `completed`).
- [ ] تست استور `useProjectStore`: بررسی منطق سورت و جابجایی پروژه‌ها.
- [ ] تست هندلر خطاهای سراسری API در `resources/js/services/api.ts` (مدیریت خطای ۴۰۱ و پاکسازی توکن).

### وظیفه ۳: آدیت و اصلاحات دسترسی‌پذیری (A11y & UX Polish)
- [ ] بررسی تمام دیالوگ‌ها و مودال‌ها (`TaskModal`, `ProjectModal`, `CommandPalette`):
  - اضافه کردن صفات `aria-modal="true"` و `role="dialog"`.
  - محدود کردن کلید Tab در داخل مودال بازشده (Focus Trap) و بستن با `Escape`.
- [ ] بررسی کنتراست رنگ‌ها در تم تاریک و روشن مطابق استاندارد WCAG AA (نسبت کنتراست حداقل ۴.۵:۱ برای متون عادی).
- [ ] ارزیابی برچسب‌های دسترس‌پذیری دکمه‌های آیکونی (`aria-label` برای دکمه‌های بستن، ستاره علاقه‌مندی، و حذف).
- [ ] اطمینان از خوانا بودن پیام‌های خطا با تگ `aria-live="polite"`.

### وظیفه ۴: بهینه‌سازی دیتابیس و حذف کوئری‌های N+1 (Database & Query Optimization)
- [ ] بررسی لاگ کوئری‌های SQL هنگام بارگذاری لیست تسک‌ها و جزئیات پروژه.
- [ ] ساخت مایگریشن ایندکس‌های کامپوزیت:
  - جدول `tasks`: ایندکس مرکب روی `[user_id, status, due_date]` و `[user_id, project_id, status]`.
  - جدول `projects`: ایندکس مرکب روی `[user_id, is_favorite, sort_order]`.
- [ ] جایگزینی تمام کوئری‌های احتمالی N+1 با Eager Loading صریح (`with(['project', 'subtasks', 'tags'])`).

### وظیفه ۵: بهینه‌سازی پرفورمنس فرانت‌اند و LCP (Frontend & Core Web Vitals)
- [ ] پیاده‌سازی Lazy Loading بر اساس مسیرها در `resources/js/router/index.ts` (Dynamic `import()` برای صفحات داشبورد، تنظیمات، و آرشیو).
- [ ] بهینه‌سازی لود فونت‌های محلی و استایل‌ها بدون بلاک کردن رندر اولیه.
- [ ] بررسی حجم نهایی باندل کلاینت و اطمینان از تفکیک Vendor Chunks.

### وظیفه ۶: اجرای فرایند ارزیابی نهایی (Verification)
- [ ] اجرای تست‌های کامل Pest در کانتینر بک‌اند:
  `docker compose exec -T app ./vendor/bin/pest`
- [ ] اجرای تست‌های Vitest فرانت‌اند:
  `docker run --rm -v "$(pwd)":/app -w /app node:22-alpine npm run test`
- [ ] اجرای سناریوهای مرورگر Playwright و ثبت بدون خطای گزارش.
- [ ] کامیت و پوش روی برنچ `feat/phase-9-qa-testing-and-optimization`.

## ۴. معیارهای پذیرش فاز ۹ (Acceptance Criteria)

1. تست‌های سرتاسری E2E تمام سناریوهای حیاتی کاربر (Auth, Tasks, Projects, Hotkeys) را بدون ارور و بدون وابستگی ناپایدار پوشش دهند.
2. هیچ کوئری N+1 در هیچ‌یک از اندپوینت‌های بک‌اند وجود نداشته باشد و زمان پاسخ‌دهی API زیر ۵۰ میلی‌ثانیه باشد.
3. تمام مودال‌ها و اینپوت‌ها به‌طور کامل با کیبورد (Tab, Arrow keys, Enter, Esc) قابل استفاده باشند و هیچ تله فوکوسی خارج از دیالوگ رخ ندهد.
4. باندل اصلی فرانت‌اند سبک و ماژولار بوده و هشداری مبنی بر چانک‌های سنگین در بیلد Vite ظاهر نشود.
5. تمامی آزمون‌های یونیت، یکپارچگی و E2E با موفقیت ۱۰۰٪ پاس شوند.
