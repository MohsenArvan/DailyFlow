# پلن پیاده‌سازی یادداشت‌های پروژه

> هر مرحله را با چرخهٔ تست ناموفق، پیاده‌سازی حداقلی و تست موفق اجرا کنید. موارد قابل اجرا با چک‌باکس مشخص شده‌اند.

**هدف** — تب مستقل «یادداشت‌ها» در صفحهٔ پروژه، با ساخت، خواندن، ویرایش، سنجاق و حذف یادداشت.

**معماری** — یادداشت‌ها زیرمجموعهٔ پروژه‌اند و API آن‌ها از مسیرهای احراز هویت‌شدهٔ پروژه استفاده می‌کند. در Vue، تب از URL خوانده می‌شود و پنل یادداشت داده‌ها را مستقل از پنل تسک‌ها بارگیری می‌کند.

**پشته** — Laravel، Sanctum، PostgreSQL، Pest، Vue 3، TypeScript، Axios، Vitest و Playwright.

**مرجع** — [سند و تصویر طرح اول](../specs/2026-11-23-project-notes.md). در نسخهٔ اول، کارت‌های سنجاق‌شده بالای فهرست خود تب یادداشت‌ها قرار می‌گیرند. صفحهٔ پروژه با تب «تسک‌ها» باز می‌شود. متن ساده است و سقف عنوان و متن به ترتیب ۱۲۰ و ۱۰٬۰۰۰ نویسه است.

## مواردی که باید در بازبینی بررسی شوند

- UUID یادداشت معتبر است ولی به پروژهٔ URL تعلق ندارد. مسیر با ۴۰۴ رد می‌شود و یادداشت تغییری نمی‌کند. مرحلهٔ ۲.
- درخواست ایجاد یادداشت هم‌زمان با حذف پروژه می‌رسد. پس از حذف هیچ یادداشت فعالی برای آن پروژه باقی نمی‌ماند. مرحلهٔ ۲.
- تغییر سنجاق در فهرست صفحه‌بندی‌شده ممکن است یادداشت را به صفحهٔ دیگری منتقل کند. پس از تغییر، فهرست دوباره از صفحهٔ اول شروع می‌شود. مرحلهٔ ۴.
- کاربر پیش از رسیدن پاسخ پروژهٔ قبلی به پروژهٔ دیگری می‌رود. پاسخ قبلی در پروژهٔ جدید نمایش داده نمی‌شود. مرحلهٔ ۴.
- ذخیره خطا می‌دهد یا کاربر با فرم تغییرکرده تب را عوض می‌کند. پیش‌نویس تا ثبت موفق یا تأیید خروج باقی می‌ماند. مرحله‌های ۵ و ۶.

## مرحلهٔ ۱ — مدل و فهرست یادداشت‌ها

- [ ] تست فهرست پروژهٔ خالی، دسترسی مهمان، پروژهٔ کاربر دیگر، جداسازی پروژه‌ها و ترتیب سنجاق را اضافه کنید. با `vendor/bin/pest tests/Feature/Project/ProjectNotesTest.php` بررسی کنید موارد جدید به‌دلیل نبود endpoint شکست می‌خورند.
- [ ] جدول با `id`، `uuid` یکتا، `project_id` با حذف آبشاری برای حذف فیزیکی، `title`، `body`، `pinned_at` nullable و timestamps بسازید. رابطهٔ `Project::notes(): HasMany` و ایندکس متناسب با فیلتر پروژه و ترتیب فهرست اضافه کنید.
- [ ] `GET /api/v1/projects/{project}/notes?page=1` را تحت `auth:sanctum` و `Gate::authorize('view', $project)` وصل کنید. از `Project::notes()` با ۲۰ ردیف در صفحه استفاده کنید. ترتیب قطعی `pinned_at IS NULL ASC, updated_at DESC, id DESC` باشد. پاسخ `data`، `links` و `meta` استاندارد Laravel را دارد. Resource فیلدهای `uuid`، `title`، `body`، `pinned_at`، `created_at` و `updated_at` را می‌دهد.
- [ ] تست مرحله را دوباره روی PostgreSQL اجرا کنید. صفحهٔ دوم و ترتیب ردیف‌های دارای زمان ویرایش یکسان را هم بررسی کنید.

## مرحلهٔ ۲ — ایجاد، ویرایش، سنجاق و حذف

**فایل‌ها** — کنترلر، مسیرها و تست مرحلهٔ ۱، درخواست‌های جدید `app/Http/Requests/Project/StoreProjectNoteRequest.php` و `UpdateProjectNoteRequest.php`، Actionهای `CreateProjectNoteAction`، `UpdateProjectNoteAction` و `DeleteProjectNoteAction` در `app/Actions/Project/`، و `app/Actions/Project/DeleteProjectAction.php`.

- [ ] تست‌های ایجاد ۲۰۱، ویرایش جزئی ۲۰۰، حذف ۲۰۴، متن فقط فاصله، سقف طول، سنجاق تکراری، ویرایش یا حذف یادداشت پروژهٔ دیگر، و حذف یادداشت‌ها در هر دو حالت حذف پروژه را بنویسید. یک تست اجرای ایجاد با نمونهٔ پروژه‌ای که پیش‌تر حذف نرم شده است اضافه کنید. همان دستور Pest را برای تأیید شکست اجرا کنید.
- [ ] `POST /notes`، `PATCH /notes/{noteUuid}` و `DELETE /notes/{noteUuid}` را زیر مسیر پروژه اضافه کنید. ابتدا Policy به‌روزرسانی پروژه را بررسی کنید و یادداشت را فقط از رابطهٔ همان پروژه پیدا کنید. عنوان و متن چندخطی پس از trim اعتبارسنجی شوند. در PATCH حداقل یک فیلد از `title`، `body` یا `is_pinned` لازم باشد. پاسخ ایجاد و ویرایش شیء `data` از همان Resource فهرست است.
- [ ] مقدار صریح `is_pinned` را به `pinned_at` تبدیل کنید. ارسال دوبارهٔ true یا false در همان وضعیت، زمان سنجاق و زمان ویرایش را تغییر ندهد. شناسهٔ پروژه و مالک فقط از رابطه و مسیر تعیین شوند.
- [ ] ایجاد یادداشت و حذف پروژه را با قفل ردیف پروژه در تراکنش هماهنگ کنید. هر دو مسیر، پروژهٔ فعال را پس از گرفتن قفل دوباره بررسی کنند. در Action حذف پروژه، یادداشت‌ها پیش از soft delete پروژه و در همان تراکنش حذف شوند. گزینهٔ فعلی حذف یا جدا کردن تسک‌ها حفظ شود.
- [ ] تست مرحله روی PostgreSQL موفق شود و رفتار تداخل ایجاد و حذف با دو اتصال تست یا بازبینی شود. `vendor/bin/pest tests/Feature/Project` باید بدون failure اجرا شود.
